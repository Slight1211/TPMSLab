# 切割前顶点吸附（vertex snapping）：0.3.8.dev0 本地改进说明

日期：2026-10-29（America/Toronto）。本地开发交付，未发布到 PyPI/GitHub，未修改 0.3.7.dev0 原始证据目录 `quality_validation_20261028/`。

## 问题根因

0.3.7.dev0 及更早版本的劣质单元尾部来自 `volume.py` 的切割方式：切割点落在背景边上的位置 `t = f_a/(f_a - f_b)` 完全由场值决定，当 `t` 接近 0 或 1 时切割点几乎贴着背景顶点，裁出的多面体带一个极薄的尖劈。随后的 `quality_fan`、`implicit_root` 和 0.3.7 的内部节点平滑都只能在事后移动点，而尖劈的瘦顶点就在界面上、被锁定，所以无法消除（0.3.7 平滑后 Diamond 低密度仍剩 288 个 Q<0.01 固体单元）。

## 改了什么

新增 `src/tpmslab/snapping.py`，按 Labelle & Shewchuk（Isosurface Stuffing, SIGGRAPH 2007）的"顶点翘曲"思路，在切割**之前**处理背景格：若某个背景顶点沿它的某条格边到切割点的距离小于边长的 `snap_alpha` 倍，就把该顶点移到等值面上、把对应不等式的值精确设为 0。切割点与顶点合并，薄片从源头不再产生。规则如下。

- 每个顶点最多移动一次，移到最近的合格切割点；默认 `snap_target="implicit"` 用二分法把顶点放到真实隐式场沿格边的根上，其它不等式取该点真实采样值；`"linear"` 则用线性切割点和线性插值值。
- 外盒面/棱/角上的顶点只能沿留在该面/棱内的格边移动，外盒不会被凹陷；导出时按坐标识别的面标签不受影响。
- 三类候选被回退并计数（`report["vertex_snapping"]`）：使任一背景四面体失去正定向；使一个背景四面体四个顶点同落一个等值面（线性场恒为零，固体和流体会同时认领）；使材料或其补集沿一条格边被"掐断"（围绕该边的四面体环中正值或负值出现两段以上）。最后一类通过逐边遍历四面体环判断，内部边按环、外盒上的边按链处理。
- 吸附在固体/流体符号翻转之前对完整不等式组执行，因此互补两相看到同一套顶点和切割键，共享界面仍然逐三角形一致。
- `snap_alpha=0`（默认）不调用吸附；已验证修改后代码在 `snap_alpha=0` 时与未修改的 0.3.7.dev0 在同一机器上生成**逐字节相同**的 points/tetra 数组（三个算例 mesh_sha256 相同）。原 Windows 证据与本机结果坐标差约 2e-15 mm、单元顺序不同，属于平台/NumPy 版本差异，与文档"不承诺跨平台字节一致"的声明一致。
- 可与 `edge_interpolation="implicit_root"` / `"quadratic_root"` 组合：`multidomain.py` 的根投影现在使用翘曲后的格点坐标（`generate_volume` 返回 `lattice_xyz`），对真实场不夹根的切点保留线性位置并计入 `report["edge_root_unbracketed_cuts"]`（12 组算例均为 0）。

入口：`Config(snap_alpha=0.25)`、`generate(Config(..., snap_alpha=0.25))`、`tpmslab generate --snap-alpha 0.25 [--snap-target linear]`、浏览器"尺寸与采样"中的 **切割前顶点吸附（α = 0.25）** 复选框（保存参数 JSON 含 `snap_alpha`，结果说明中显示移动/回退顶点数）。推荐 `snap_alpha=0.25`（L–S 长边取值）；0.3～0.4 仍可生成但回退数迅速增加，收益很小。

解读：

- 几何不变量：12/12 界面审计通过（无缺失/重复/非流形面）；12/12 外盒面节点仍精确在面上且所有节点在盒内；固体+流体体积等于盒体积；P1 标量扩散 patch 检查 36/36 通过。
- 质量改善：Q<0.01 单元 2710→1；Q<0.1 单元 60217→250；逐相最小质量从 0.0004～0.013 提高到 0.009～0.18；p01 提高 3～30 倍；中位质量从 0.35～0.57 提高到 0.60～0.76；单元数约减半（薄片和多余切割点消失）。在吸附网格上再跑 0.3.7 的内部平滑几乎无事可做，3 组因中位质量门槛而回退，属于正常的"无改进则不接受"。
- 几何代价：吸附改变分片线性近似。固体密度绝对误差中位数 1.52→1.51 pp 基本不变，但最差算例（Diamond 高密度）从 +3.66 升到 +4.03 pp；界面节点 RMS 偏差升高 10～25%（在 5 mm 盒、resolution=12 下为 10～40 µm，约为格距的 3～10%），最大偏差不变或下降。`snap_target="linear"` 的密度误差更差（中位 1.78、最大 4.48 pp），因此默认用隐式根。
- 不做的结论：CG 迭代数普遍下降（约 300→100）主要来自自由度减半和条件数改善，不是对真实求解器加速的证明；没有 COMSOL 工况、收敛研究或与其它网格器的精度对比；界面偏差只是一阶估计。

## 与隐式求根组合（`snap_alpha=0.25` + `edge_interpolation="implicit_root"`）

吸附只把被移动的顶点放到真实根上，其余切点仍是线性插值位置，因此基线固有的 +0.5～+3.7 pp 密度偏差（薄片被线性插值放大）没有消除。把吸附与 0.3.5 的根投影组合后，所有界面节点都落在隐式面上（界面 RMS 偏差 → 0），密度误差中位数 1.52 → 0.69 pp、最大 3.66 → 2.03 pp，同时保留吸附的质量尾部收益；单独使用根投影虽然密度误差更低（中位 0.44 pp），但 Q<0.01 单元从 2710 增到 3035。剩余误差来自更粗的分片平面近似（吸附后界面三角形更少更大），需要提高 resolution 才能继续下降。

## 已知限制与下一步

- 吸附+求根后仍有 +0.3～+2.0 pp 的正向密度偏差，来自分片平面近似本身；只能靠提高 resolution 或引入二阶单元/曲面逼近。
- 在立方六四面体格上没有二面角下界的理论保证（L–S 的保证针对 BCC 格）；Gyroid 高密度流体仍剩 1 个 Q<0.01 单元。
- 顶点级"掐断"（两块材料只在一个吸附顶点相触）未检测；它不破坏边流形性，与基线中由薄片连接的同类构型等价，但 COMSOL 可能提示非流形点。
- `tpmslab init-config` 写出 `snap_alpha`/`snap_target` 字段；旧 JSON 缺少这些字段时按默认值 0 处理，与 0.3.7 行为一致。

## 复现

```sh
python -m pip install -e ".[test]"
python -m pytest -q                      # 195 项（含 tests/test_snapping.py 11 项）
python benchmarks/snapping_study.py --out new_snap_validation --alpha 0.25 --save-meshes
```

`--out` 必须是新目录。每个算例写出 `<case>.json`、`<case>_baseline/`、`<case>_snapped/`、`<case>_snapped_conditioned/`、`<case>_snapped_root/`，汇总在 `comparison.csv`、`summary.json`、`sha256.json`。本文第一组表来自 `snap_validation_20261029`（三变体），第二组表来自 `snap_validation_20261029b`（四变体）；两次运行的基线与吸附结果一致。
